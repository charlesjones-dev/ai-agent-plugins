## iOS simulators

Past sessions created new simulators again and again, and left them booted after the work ended. Each booted simulator uses memory and CPU until someone shuts it down. These rules cover iPhone, iPad and Apple Watch simulators.
{{#reuse}}

### Reuse a simulator

- Before you boot or create a simulator, list the ones that exist with `xcrun simctl list devices available`.{{#t3}} In T3 Code, `device_list` shows them too.{{/t3}}
- Pick a simulator in this order:
  1. The simulator that the project names. Look in the project's `CLAUDE.md`, its KB, its `scripts/` folder and its CI config. Some projects have their own named simulators, such as "Acme iPhone 17 Pro Max" or "Acme iPad Air".
  2. A simulator that is already booted and has the device type and runtime you need.
  3. A simulator that Xcode made for the device type and runtime you need, such as "iPhone 17 Pro" on iOS 27.0.
- Create a simulator only when no existing one has the device type and runtime you need. Start its name with the project name, such as "Acme iPhone 17 Pro", so the next session finds it. Check first that no simulator has that name and runtime. Say in the reply that you created it.
- Don't create a simulator to get a clean app state. Uninstall the app with `xcrun simctl uninstall <udid> <bundle-id>` instead.
- Several simulators share a name on different runtimes. Refer to a simulator by its UDID, not its name. With `xcodebuild`, use `-destination 'id=<udid>'`, so it doesn't boot a second simulator.
- Don't delete a simulator unless the user asks.
{{/reuse}}
{{#shutdown}}

### Shut down simulators when done

- Before you boot anything, run `xcrun simctl list devices booted` and note the UDIDs. The user or another session uses these simulators. Leave them booted.
- When the work no longer needs a simulator, shut it down with `xcrun simctl shutdown <udid>`. Do this before the reply that ends the turn, even when the task failed or the user stopped it.
- Shut down every simulator you used that wasn't booted before you started. This includes simulators that `xcodebuild`, a test run or a project script booted for you. It also includes a paired Apple Watch simulator.
{{#t3}}
- If you opened a simulator with T3's `device_open`, close it with `device_close` and `shutdown: true`. That removes it from the Device panel and shuts it down.
{{/t3}}
- Don't shut down a simulator that you didn't use. Another Claude session may be using it.
- Keep a simulator booted only when the user needs it, for example to check a result on screen. Say in the reply which simulator stays booted and why. Shut it down in the next turn, after the user says they're done with it.
- A background test run that uses a simulator counts as running work. Shut the simulator down when that run finishes.
- A subagent that uses a simulator must shut down the simulators it booted before it reports back. Put this rule in its prompt.
{{/shutdown}}
