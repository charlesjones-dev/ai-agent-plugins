## T3 Code context handoff

These rules apply in a session that has T3 Code's tools.

- When this thread's context window is nearly full and work is still left, start a new T3 thread for the rest. Don't wait for the harness to compact the conversation, because a summary loses details that the work needs.
- Take these as signs that the context is nearly full: the harness says the context is low, the conversation was just compacted or summarized, or the thread has run through many long tool outputs and still has a large part of the work ahead.
- Don't ask first. This rule is the user's standing request for the new thread.
- Move at the next clean point. First finish the current step, and commit, push or write down everything that exists only in this thread. Don't move while a background command, subagent or delegated task still reports back to this thread.
- The new thread can't see this one. Write a prompt that carries all it needs:
  - the goal and the parts of the work, in order;
  - the files to read first;
  - where things stand: branches, commits, PRs, what is deployed, and what is checked;
  - the user's decisions and standing instructions, with their dates, and every open item with its full details;
  - the rules that apply, the lessons this thread learned, and the next step.
- Launch it with `t3_thread_launch`. When the work is in this thread's worktree, bind the new thread to that worktree (`workspaceStrategy` with `existing_worktree`), so local branches and unpushed commits stay available. Tell the new thread to link the PRs it takes over.
- After the launch, this thread does no more work on the task. In its last reply, give the new thread's link and list the open items that moved there. Those items count as closed in this thread. If your instructions give an ending for a finished thread, use it.
