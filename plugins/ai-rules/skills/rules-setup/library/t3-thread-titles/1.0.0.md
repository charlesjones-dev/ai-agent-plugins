## T3 Code thread titles

The T3 Code mobile app shows a thread's title and a small project icon. It doesn't show the project name. A project name at the start of the title lets the user tell threads apart in the list.

- Give every top-level thread in a T3 project a title in this form: `<project name>: <title>`, such as `demo-app: Scan queue retries`. The project name is the T3 project's title, written exactly as T3 shows it. Don't shorten it, and don't use the folder name or the repo name in its place.
- Don't add a project name to a thread in "No project", whose folder is under `~/.t3/scratch`. Don't rename a subagent's thread or a delegated child thread.
- **Your own thread.** In the first turn of a thread, check the title just before the final reply. By then T3 has written its own title. T3 tools are deferred, so load them with ToolSearch first.
  1. Call `t3_thread_list` with `limit: 5` and no project. The result gives this thread's id as `currentThreadId`, the id of its project as `projectId`, and each thread's title.
  2. Call `t3_project_read` with that `projectId` to get the project's title.
  3. If this thread's title doesn't start with the project name and a colon, rename the thread with `t3_thread_update` and `action: "rename"`. Keep the title that T3 wrote, and put the project name in front of it. If that title is "New thread" or a cut-off copy of the user's first message, write a title of 3 to 8 words instead.
- Do this check once for each thread. Check again only when the user asks for a new title.
- **Threads and tasks you create.** Start the `title` you pass to `t3_thread_launch`, `create_threads` and `schedule_task` with the project name. Use the project that the new thread runs in. It can differ from this thread's project.
- Don't call `t3_thread_update` with `action: "regenerate_title"`. T3 writes the new title without the project name. To change a title, use `action: "rename"` and keep the project name at the start.
