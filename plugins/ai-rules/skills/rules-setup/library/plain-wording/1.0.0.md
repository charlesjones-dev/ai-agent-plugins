## Plain wording

These rules apply to everything a person reads: chat replies, PR descriptions, commit messages, docs, and messages the user sends to other people. They come from ASD-STE100 Simplified Technical English, without its approved-word dictionary.

- Use one name for one thing. After you name something (a server, branch, environment or person), use the same name every time. Don't switch to a synonym.
- Keep noun stacks to three words or fewer. Write "the backup command for the staging MongoDB volume", not "the staging MongoDB volume backup command".
- Put one idea in each sentence. Don't use a semicolon, dash or brackets to add a second fact. Write a second sentence instead.
- Use the active voice. Write "Railway rejected the plan", not "the plan was rejected".
- Put a warning before the step it applies to, not after it.
- Don't use idioms or figures of speech. Write "this fails", not "this falls over".
- Technical names (tools, commands, env vars, file names) are fine. If the reader may not know one, explain it the first time it appears.
